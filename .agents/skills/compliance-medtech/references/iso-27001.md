# ISO 27001:2022 — key controls (Pakiet Spokoju)

Focus: **Annex A** controls that map to software, cloud SaaS, and Secure by Design. Full ISMS (context, risk assessment, Statement of Applicability, management review) remains an **organizational** programme — this file covers what code and ops in this repo must support.

Load for access control, logging, secure development, cryptography, supplier security, or “ISO audit readiness” of a change.

---

## 1. ISMS vs engineering (do not confuse)

| ISMS (organization) | Engineering (this repo) |
|---------------------|-------------------------|
| Risk assessment, SoA, policies, training | Implement technical controls consistently |
| Management commitment, internal audit | Evidence in code: RLS, `audit_logs`, secrets, reviews |
| Certification body | Agent can only prepare **technical** readiness |

Always point gaps that are **process-only** (training, HR, physical office) separately from **code** gaps.

## 2. Control themes (ISO 27001:2022 Annex A)

Grouped as in the standard: Organizational (A.5), People (A.6), Physical (A.7), Technological (A.8).

### A.5 Organizational (selected, product-critical)

| Control | Intent | Repo / ops expectation |
|---------|--------|-------------------------|
| **A.5.1** Policies | Security policy exists | `SECURITY.md` maintained; agents follow it |
| **A.5.2** Roles | Clear security roles | `app_role` enum; no privilege creep in policies |
| **A.5.3** Segregation of duties | Split conflicting duties | Separate human roles; `iot_device` ≠ nurse; no shared DFCMS credentials |
| **A.5.7** Threat intelligence | Awareness of threats | Track dependency/CVE issues for Edge/JS deps when added |
| **A.5.8** Project security | Security in projects | Review auth/RLS/Edge on every relevant PR |
| **A.5.10** Acceptable use | Rules for assets | No production data in personal tools / pasted into chats carelessly |
| **A.5.15** Access control | Rules for access | Auth + RLS + tenant filter |
| **A.5.16** Identity management | Lifecycle of IDs | Profiles tied to `auth.users`; disable/offboard process (ops) |
| **A.5.17** Authentication | Auth info protected | Supabase Auth; never log passwords/tokens |
| **A.5.18** Access rights | Provisioning | Role changes audited; least privilege |
| **A.5.19–A.5.21** Supplier | Supplier security | Supabase, Cloudflare, OpenAI under DPA/security review |
| **A.5.23** Cloud services | Cloud use security | Single intended projects: Pages `smart-senior`, Supabase `bmughdoqdsjfstxnnjks` |
| **A.5.24–A.5.27** Incident | Incident management | Runbook (ops); technical forensics via `audit_logs` |
| **A.5.29–A.5.30** Disruption | Business continuity | Backups/restore (Supabase); deploy rollback plan |

### A.6 People (selected)

| Control | Intent | Expectation |
|---------|--------|-------------|
| **A.6.1–A.6.3** Screening, terms, awareness | Human risk | Org process; engineers follow Secure by Design |
| **A.6.8** Reporting | Report events | Path in `SECURITY.md` (`kontakt@dfops.eu`) |

### A.7 Physical (selected)

Mostly **cloud provider** responsibility (Supabase/CF data centres). Local: protect laptop access, no printed resident lists without controls (ops).

### A.8 Technological (core for this codebase)

| Control | Intent | Repo expectation |
|---------|--------|------------------|
| **A.8.1** Endpoint devices | User device security | Ops; prefer no long-lived secrets on disks in git |
| **A.8.2** Privileged access | Admin rights limited | `superadmin` rare; `service_role` never in client |
| **A.8.3** Information access | Need-to-know | RLS; family view; staff scoped by org |
| **A.8.5** Secure authentication | Strong auth | Supabase Auth; MFA TOTP (`aal2`) for privileged staff on sensitive tables (ADR-011) |
| **A.8.7** Protection against malware | Malware | Dependency hygiene; no arbitrary `eval` of user content |
| **A.8.8** Technical vulnerabilities | Patch/manage | Keep CLI/runtime updated; fix known vulns in functions |
| **A.8.9** Configuration management | Secure config | `.env.example` only; no prod secrets in git; Wrangler project name pinned |
| **A.8.10** Information deletion | Secure deletion | Retention/erasure jobs for patient data (to implement/process) |
| **A.8.11** Data masking | Reduce exposure | `pesel_hash`; family `family_daily_reports` (no `raw_data`); redact in UI errors |
| **A.8.12** Data leakage prevention | Stop exfil | No `raw_data` to family; no secrets in Pages; CORS/auth on Edge |
| **A.8.13** Backup | Copies | Supabase backups; verify restore (ops) |
| **A.8.15** Logging | Logs | `audit_logs` on UPDATE/DELETE; Edge request logging without sensitive bodies |
| **A.8.16** Monitoring | Detect anomalies | Ops/alerting TBD — flag as gap if claiming full ISO ops maturity |
| **A.8.24** Cryptography | Crypto use | TLS; hash PESEL; store secrets in vaults (Supabase Secrets / CF) |
| **A.8.25** Secure development life cycle | SDLC | Migrations + RLS together; security review; no medical logic on FE |
| **A.8.26** Application security requirements | Security reqs | This skill + `SECURITY.md` as requirements input |
| **A.8.27** Secure system architecture | Architecture | Frontend UI only; Edge for AI; DB RLS |
| **A.8.28** Secure coding | Coding practices | Parameterized SQL/RPC; validate Edge input; least data in errors |
| **A.8.29** Security testing | Test in SDLC | Manual/automated checks on RLS policies; never skip for “MVP” |
| **A.8.31** Separation of environments | Dev/test/prod | Distinct projects; never use DFCMS project for this app |
| **A.8.32** Change management | Controlled changes | Migrations via CLI; document in MASTER_CONTEXT §10 |
| **A.8.33** Test information | Protect test data | No production patient dumps in fixtures |
| **A.8.34** Protection of information systems during audit | Safe audits | Read-only audit access; don’t disable RLS “for debugging” in prod |

## 5. ISO review checklist (copy)

```
ISO 27001 (technical):
- [ ] Change covered by security policy / Secure by Design
- [ ] Access: Auth + RLS + correct roles; no privilege escalation
- [ ] Privileged secrets not in client/git/Pages
- [ ] Audit trail for UPDATE/DELETE on tenant data
- [ ] Secure coding: validate Edge inputs; no medical logic in browser
- [ ] Config: correct Supabase project-ref and CF project name
- [ ] Logging does not store secrets or unnecessary health payloads
- [ ] Test data is non-production
- [ ] Supplier impact considered (OpenAI/Supabase/CF)
- [ ] Residual gaps tagged process vs code
```
